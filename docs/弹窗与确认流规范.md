## 一、确认流分级

按「误触代价」分三级，交互强度递增：

| 等级 | 定义 | 交互定标 |
|---|---|---|
| 常规 | 可逆或零代价 | 直接执行，不弹确认；结果以 toast/就地状态反馈 |
| 破坏性 | 有实质代价但可恢复/可重建 | 一次确认：弹窗确认后执行（单按钮确认即可） |
| 不可逆 | 永久损失，无法恢复 | 二次确认或显式列出损失清单；确认按钮用危险/主 accent 色 |

分级实例：

| 操作 | 等级 | 理由 |
|---|---|---|
| 装备/卸下遗物、领取挑战 | 常规 | 即时可逆或零代价 |
| 合成 | 破坏性 | 3 件材料永久消耗；选材完成即确认，无二次弹窗 |
| 挂机驻扎 | 破坏性（轻） | 改变据点状态，可撤回 |
| 编队全入/全撤 | 破坏性 | 大幅改动编队，可手动还原 |
| 导入存档 | 不可逆 | 全量替换当前进度，替换后不可恢复 |
| 转生（奇点重启） | 不可逆 | 大进度重置（保留清单明确列出） |
| 清除存档 | 不可逆 | 全部数据永久清除 |
| 丢弃遗物 | 不可逆 | 稀有物品永久丧失 |

## 二、ModalOverlay 结构标准

全站唯一弹窗基础组件（离线报告已于 v0.87 并入本组件，全站单轨；确认流共用骨架见 §二之二）：

| 项 | 定标 |
|---|---|
| 文件 | `src/components/ui/ModalOverlay.vue` |
| 结构 | 遮罩 + `role="dialog"` + `aria-modal="true"` + `aria-label` |
| 宽度 | max-width 360px，遮罩内边距恒定 16px、弹体内边距恒定 24px（无断点区分） |
| 阴影 | `--elevation-3` |
| 入场 | modalIn 0.25s（《动效规范》时长总表定标） |
| 焦点 | useFocusTrap：打开聚焦陷阱内、Tab 循环不逃逸 |
| 关闭 | Escape = 点击遮罩同语义，emit `overlayClick` 交使用点决定（组件不自毁状态） |
| 尺寸 | 内容超高时弹体内部滚动（max-height 85vh） |

按钮排布定标：双按钮时「取消」在左（次按钮）、「确认」在右（主/accent 按钮）；默认等宽 1:1，挂机驻扎传 `confirmFlex=2` 为 2:1。不可逆操作的确认按钮用 accent 危险色或琥珀/红色语义。

### 二之一、全局层级定标（z-index 唯一出处）

| 层 | 元素 | z-index | 说明 |
|---|---|---|---|
| 背景 | 星云 / 星点 / 暗角 | 0 | 纯装饰 |
| 内容 | `#app` | 1 | 页面根 |
| 顶栏 | TopBar | 40 | — |
| 侧栏 / 底栏 | SideNav / BottomNav | 50 | — |
| 引导气泡 | OnboardingBubble | 60 | 高于导航；根节点不携带 position/z-index，定位与层级由父级 `.ob-*` 变体类承载（v0.97 定标实现） |
| 弹窗遮罩 | `.modal-overlay` | 200 | 本册结构标准 |
| 提示浮层 | toast / 跃迁闪光 | 300 | 高于弹窗，提示不被埋 |
| 成就播报 / 层完成仪式 | AchievementToast / LayerCompleteCeremony | 400 | 同带并列：播报为提示性浮层，层完成仪式为全屏叙事浮层 |
| 转生仪式 | CeremonyOverlay | 500 | 全屏叙事浮层，压过播报带 |
| 错误屏 | App 启动错误屏 | 999 | 最高层：存档不可读等致命态须盖住一切 |

定标链条：modal 200 < toast 300 < 播报与层完成 400 < 转生仪式 500 < 错误屏 999。
新增浮层/弹窗按此带取值，不得跳号；跨带调整须先改本表再动代码。

### 二之二、确认流共用骨架 ConfirmModal

v1.07 起，双按钮确认流共用 `ConfirmModal.vue`（ModalOverlay + 取消/确认按钮组），各确认流只传文案与语义色：

| 项 | 定标 |
|---|---|
| 文件 | `src/components/ui/ConfirmModal.vue` |
| 结构 | ModalOverlay + 取消/确认按钮组；确认按钮默认 `--color-alert`，可按场景注入 accent |
| Props | `confirmText` / `accent` / `stretch` / `confirmFlex` |
| 默认宽度 | 取消 1 : 确认 1；`confirmFlex=2` 时为 2:1（挂机驻扎） |
| 消费点 | SavePanel（导入、清档）、FormationPanel（批量编队）、GarrisonModal（驻扎）、PrestigeView（转生）共 5 处 |

## 三、各确认流定标

### 转生（奇点重启）：不可逆

- 弹窗：ModalOverlay，aria-label「确认奇点重启」
- 标题：确认奇点重启？
- 正文：⚠️ 警告框**列出重置清单**（所有资源（暗物质部分保留）/所有建筑等级/所有科技进度…）与保留项
- 按钮：取消（次）/ 确认重启（accent 琥珀）
- 触发：转生页主按钮 → 弹窗 → 确认执行

### 清除存档：不可逆

- 弹窗：ModalOverlay，aria-label「确认清除存档」，标题红色
- 正文：⚠️ 此操作将**永久清除**以下全部数据，不可恢复（全量清单）
- 执行后 `location.reload()` 新档启动

### 导入存档：不可逆

- 入口：设置页存档管理区「导入存档」
- 交互：**点击导入先弹确认**，三段文案：
  - 标题「确认导入存档？」
  - 正文「导入将完全替换当前存档，当前进度不可恢复。」
  - 按钮「确认导入」
- 确认后才执行解析校验与全量替换（替换流程见《存档与数据安全规范》§六）
- 解析失败 toast 说明，不触碰现有存档

### 挂机驻扎：破坏性（轻）

- 弹窗：ModalOverlay，aria-label「挂机驻扎确认」
- 标题：挂机驻扎；正文：据点名 + **预期收益预览**（每资源每秒/每小时 + 离线结算提示）
- 按钮：取消 / 确认驻扎（accent 绿，flex 2:1）

### 编队全入 / 全撤：破坏性

- 弹窗：ModalOverlay（批量操作确认）
- 触发阈值：全入看 `owned > 100`；全撤看在编数 `inFormation > 100`
- 文案：正文「即将编入/撤出 N 名士兵」，当前不含兵种名；如需显示兵种名须同步改文案与测试
- 按钮：取消 / 确认（accent）

### 丢弃遗物：不可逆（轻量场景免弹窗）

- 不用弹窗：按钮双击确认机制
- 第一次点：按钮变「确认丢弃？」（pending 态，3 秒有效）
- 3 秒内再点：执行丢弃；3000ms 超时自动复位（无全局点击复位监听）
- 已装备遗物禁用丢弃（按钮禁用 + 提示「请先卸下」）

## 四、非确认弹窗

### 战斗结算（胜负结果）

- 弹窗：ModalOverlay；胜利显示奖励清单，失败显示损失
- 按钮随胜负变化：胜利「留在此据点」（主，flex 2）+「返回星图」（次，flex 1）；失败「确认」
- 奖励在战斗结算时即时发放（v0.94），结果弹窗仅做展示，关闭或离开页面不影响战果

### 离线收益报告

- 现状：已并入 ModalOverlay（v0.87，modalIn 0.25s 与全站统一，focus trap 走组件内置）

### 强化/合成弹窗

- 弹窗：ModalOverlay（modal-class 区分强化/合成）
- 强化弹窗关闭即取消；合成在点击执行时已永久消耗 3 件材料，结果弹窗关闭不返还，选材完成即视为确认

## 五、验收清单

| 验收项 | 标准 |
|--------|------|
| 确认流分级 | 每处确认按 §一 分级表可归级 |
| 不可逆三项 | 转生/清档/导入均有确认弹窗且列出损失或替换语义 |
| 导入二次确认 | 点击导入先弹确认，确认后执行 |
| 弹窗结构 | 全站弹窗走 ModalOverlay（离线报告统一后零双轨） |
| 焦点行为 | 打开聚焦、Tab 循环、Escape 关闭 |
| 丢弃双击 | pending 3s 机制生效，已装备禁用 |
